## 一、初始设计动机（2026-05-30）

**设计目标**：
1. 理解中文分词的核心原理（规则法 vs 统计法）
2. 实现经典算法（FMM/BMM/HMM）作为基线
3. 设计混合模型，结合两者优势
4. 与工业级工具（jieba）对比，分析差距

### 1.2 为什么选择三层混合架构？

**初始想法**（plan.md 阶段2第3点）：
```
Layer1: FMM匹配词典中的已知词
Layer2: 对未匹配的连续单字，用HMM进行分词
Layer3: 用简单规则处理数字、日期、英文单词等特殊实体
```

**设计动机**：
- **Layer1（规则法）**：速度快，可解释性强，处理已知词效果好
- **Layer2（统计法）**：不依赖词典，能处理部分未登录词
- **Layer3（规则法）**：处理特殊实体，规则明确，100%准确

**理论依据**：
- 工业级分词系统（如jieba、pkuseg）都采用混合架构
- 规则法和统计法各有优劣，混合可以扬长避短
- 分层处理符合"先易后难"的认知逻辑

### 1.3 为什么选择BiMM而非单独FMM或BMM？

**FMM的局限**：
- "研究生命起源" → `研究生/命/起源`（错误）
- 正向贪心容易在交集歧义处犯错

**BMM的优势**：
- "研究生命起源" → `研究/生命/起源`（正确）
- 逆向匹配在某些歧义场景下表现更好

**BiMM的设计**：
- 融合FMM和BMM的结果
- 通过启发式规则选择最优解
- 期望获得比单一方向更好的效果

**融合规则**（初始设计）：
1. 若FMM和BMM结果一致，直接输出
2. 若结果不一致，优先选择词数更少的结果
3. 若词数相同，选择单字数量更少的结果
4. 若单字数量也相同，选择逆向匹配结果

## 三、第一次优化提案与用户异议（2026-05-31上午）

### 3.1 我的初始优化方案

基于问题分析，我提出了三个改进方向：

**方案1：优化Layer2触发条件**
```python
def _layer2_segment(text, dictionary, max_len, hmm_params):
    if len(text) >= 4:
        oov_ratio = sum(1 for c in text if c not in dictionary) / len(text)
        if oov_ratio > 0.5:
            return hmm_segment(text, hmm_params)
    return bimm(text, dictionary, max_len)
```

**理由**：减少不必要的HMM切分，避免长句过碎

**方案2：增强BiMM融合规则**
```python
# 新增规则3：计算平均词长，选平均词长长的
f_avg_len = sum(len(w) for w in f_result) / len(f_result)
b_avg_len = sum(len(w) for w in b_result) / len(b_result)
if abs(f_avg_len - b_avg_len) > 0.1:
    return f_result if f_avg_len > b_avg_len else b_result
```

**理由**：在词数和单字数相同时，提供第三优先级判断

**方案3：补充OOV词典新词**
- 添加"多模态大模型"、"具身智能机器人"等2024-2025热词

**理由**：提升词典覆盖率

### 3.2 用户的四条深刻异议

#### 异议1：Layer2触发条件存在逻辑硬伤

**用户指出**：
> "oov_ratio计算逻辑错误：在`_layer2_segment`中，`text`是由连续单字拼成的字符串，其中每个字都`not in dictionary`（这是`hybrid_segment`第35-39行的收集条件）。所以`oov_ratio`永远等于1.0，这个条件形同虚设。"

**我的验证**：
```python
# hybrid_segment.py 第38-43行
if len(w) == 1 and w not in dictionary:  # ← 收集条件
    buf = w
    i += 1
    while i < len(words) and len(words[i]) == 1 and words[i] not in dictionary:
        buf += words[i]  # ← buf中的每个字符都不在词典中
        i += 1
```

**结论**：用户完全正确！`oov_ratio = len(buf) / len(buf) = 1.0`，永远满足`> 0.5`，该条件等价于`if len(text) >= 4`，是冗余代码。

**教训**：未追踪数据流就提出优化方案，导致逻辑错误。

---

#### 异议2：BiMM平均词长规则存在数学错误

**用户证明**：
> "当词数相同、单字数也相同时，平均词长必然相同（因为`总字数/词数 = 平均词长`，而总字数固定），所以`abs(f_avg_len - b_avg_len) > 0.1`这个条件永远不会成立。这是一个数学上的逻辑错误。"

**数学证明**：
- FMM和BMM处理同一句子 → 总字数`total_chars`相同
- 若词数相同：`len(f_result) == len(b_result) == word_count`
- 则：`f_avg_len = total_chars / word_count`
- 且：`b_avg_len = total_chars / word_count`
- 因此：`f_avg_len == b_avg_len`，`abs(f_avg_len - b_avg_len) = 0`
- **结论**：`abs(...) > 0.1`永远不成立

**我的反思**：
- 这是严重的数学疏忽
- 添加规则前未进行基本的代数验证
- 用户通过严谨的数学推导发现了逻辑漏洞

**教训**：算法设计必须进行数学推导，不能凭直觉。

---

#### 异议3：OOV词典补充方向对但粒度问题未解决

**用户指出**：
> "看实际数据：自研BiMM=`黑神话悟空/带动/谷子经济/升温`，jieba=`黑/神话/悟空/带动/谷子/经济/升温`。自研词典收录了'黑神话悟空'等整体词，但jieba把它们拆成更小粒度。这不是词典不够，而是词典粒度与jieba不同。"

**深层分析**：
- 当前dict_oov.txt只有粗粒度词（"黑神话悟空"）
- BiMM贪心策略总是选择最长匹配
- jieba使用细粒度标注标准
- **本质矛盾**：标注标准差异，非算法缺陷

**用户的建议**：
> "补充词典的方向对，但应该同时提供细粒度词（如'黑神话''悟空''新质''生产力'），而非只提供粗粒度整体词。或者，在评估时承认粒度差异不是错误。"

**我的认同**：
- 用户准确把握了问题的本质
- 单纯补充长词会加剧与jieba的差异
- 需要在报告中说明评估指标的局限性

---

#### 异议4：英文实体识别是中文分词的完整性问题

**用户的核心论点**：
> "核心任务确实要求输入为中文文本，但这不等于中文文本中不会出现英文词汇。现代中文语境中嵌入英文术语是普遍现象，而非边缘情况。"

**用户的证据**：
- 科技领域：DeepSeek、Agent、RAG、AIGC、Sora
- 生活方式：Citywalk、Kimi
- "年轻人热衷Citywalk和搭子社交"是一句完全自然的中文

**用户的关键洞察**：
> "问题的本质不是'要不要处理英文'，而是'中文分词模型能否正确处理中文文本中自然出现的英文术语'。如果模型把Citywalk切成C/it/yw/a/lk，这不是英文处理能力不足，而是中文分词的完整性缺陷——一个完整的语义单元被拆碎了。"

**用户的修复方案**：
> "调整Layer顺序，在BiMM之前先保护英文实体：apply_sentence_entities(先提取英文/数字/日期) → BiMM(只处理剩余中文片段) → HMM → merge_entities。这不是新增功能，只是激活已有代码，改动极小。"

**用户的兼容性说明**：
- 输入仍然是中文文本，英文术语只是中文文本的组成部分
- 模型仍然是中文分词模型，不需要具备英文分词能力
- 只需识别"连续英文字母是一个不可分割的token"，这和识别"连续数字是一个token"是同一类规则
- 符合plan.md中阶段2第3点"用简单规则处理英文单词等特殊实体"的设计

**我的震撼**：
- 用户完全颠覆了我的认知
- 我之前认为"题目要求输入为中文，无需处理英文"
- 但用户指出：现代中文文本中嵌入英文是普遍现象
- 更重要的是：Layer3的正则`RE_ENGLISH`已经具备识别能力，只是执行顺序导致失效

## 四、修正后的优化方案（2026-05-31中午）

### 4.1 采纳用户异议，重新设计方案

基于用户的四条异议，我完全重构了优化方案：


## 七、最终设计的全貌

### 7.1 完整的四层架构

```
Layer0: 实体预处理（新增）
  ├─ 提取英文：RE_ENGLISH = [A-Za-z][A-Za-z0-9+#]*
  ├─ 提取日期：RE_DATE = \d{4}年\d{1,2}月\d{1,2}日
  ├─ 提取数字：RE_ARABIC_NUM = \d+(?:\.\d+)?
  └─ 提取中文数字：RE_CN_NUM = [零一二三四五六七八九十百千万亿]+

Layer1: BiMM词典匹配
  ├─ FMM正向最大匹配
  ├─ BMM逆向最大匹配
  └─ 融合规则：词数→单字数→BMM优先

Layer2: HMM统计分词
  ├─ 触发条件：连续未登录单字长度>=4
  ├─ BMES标签体系
  └─ Viterbi算法（O(4)空间优化）

Layer3: 后处理合并
  └─ merge_entities() 合并相邻实体
```
